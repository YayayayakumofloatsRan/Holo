## 一句话定位

Holo Kernel v4 是一个面向复杂金融研究任务的通用单智能体运行框架。系统目标是构建稳定的模型驱动行动闭环：大模型先理解任务，再发现并调用工具，随后读取证据并完成计算核验，最终形成答案；宿主程序负责验证工具协议并执行工具，同时记录事件并管理上下文，还要保护安全边界，FinanceBench 题目不能被写成规则表或答案表。

## 与最终报告规范的对应关系

`要求.txt` 作为内部约束文件，规定最终报告应说明系统如何在真实任务中获取信息并做出行动决策，随后完成结果验证，同时讨论评测结果和失败原因与能力边界。正式论文正文不应写成对外部说明文件的回应，也不应出现提交目的自述。Holo 的对应关系如下：

| 报告规范 | 本项目对应内容 |
| --- | --- |

| 智能体主线 | Kernel v4 将用户输入转化为持续推进的任务状态，使模型能够在行动与观察之间反复核验，直到形成最终答案。 |
| 技术复杂性 | 系统把模型原生工具调用与流式工具执行纳入证据对象管理，并通过 SEC/EDGAR 检索支撑文档读取和表格处理，再结合计算器与数值核验完成金融任务。 |

## 从项目建议书到最终系统

项目建议书中提出 Holo 的目标是搭建完整智能体行动闭环基座，并特化用于金融基本面研究。最初设想要求系统把用户输入与记忆系统纳入同一个循环，并让检索工具和本地数据脚本共同服务于系统推理，行动反馈也会回到下一轮任务推进中。

实际迭代后，项目重点收敛为：

1. 放弃 v3 中过重的金融语义闸门，重写一个通用单智能体循环。
2. 参考成熟开源智能体项目的核心思想，将流式工具执行和工具调用上下文吸收到新循环中，同时保留工具结果生命周期与工具发现能力，并支持取消控制以及上下文编辑。
3. 将金融能力作为工具链和系统提示合同暴露给模型，宿主程序不打表，也不强行替模型补槽。
4. 用 live benchmark 结果证明系统真实做题能力，并记录失败类型和成本。

这条路线和建议书目标一致：Holo 的核心贡献是一个可扩展的大模型运行框架基座，金融问答脚本只是验证该基座能力的应用形态。

## 系统架构

### 核心循环

Kernel v4 的主循环由以下组件组成：

- `SingleAgentLoop`：单智能体行动循环，控制轮数和预算，并处理最终回答与异常退出。
- `OpenAICompatibleChatProvider` / `DeepSeekChatProvider`：把工具以模型服务支持的函数格式暴露，并解析流式工具调用。
- `StreamingToolExecutor`：模型在输出过程中发起工具调用后，宿主程序立即执行工具并记录生命周期。
- `ToolUseContext`：保存对话消息和运行元数据，并管理证据对象以及进行中的工具调用。
- `WorkflowObserver`：实时暴露模型开始事件，随后记录工具执行情况和结果返回过程，最后记录循环结束状态。
- `artifact.inspect/search/read`：把大文档和大工具结果转成可检索且可按窗口读取的证据对象。
- `tool.discovery` / `finance.workbench.open`：让模型按任务需要发现工具族和金融工具台，宿主程序只负责暴露能力和执行边界。

### 金融工具面

当前金融能力主要来自以下工具族：

- SEC/EDGAR 文件发现与文件展开，用于取得官方公开披露；
- 公司文件和网页文档抽取，用于读取年报和季报，也覆盖公告以及代理投票材料；
- 证据对象搜索和窗口读取，用于处理长文件和大工具结果；
- FQA/FinQA 风格上下文解析，用于处理题目自带表格或文本；
- 表格查询和转换，用于完成排序与聚合，并支持筛选以及派生指标计算；
- 计算器与符号计算，用于公式替换和比例计算，也支持单位换算；
- 财年日期和天数工具，用于处理财年起止日和 period day count；
- 数值核验器，用于检查最终答案中的关键数字；
- 金融工具台模板覆盖多类题型，从库存效率和毛利率，到营运资本与资本密集度，再到法律事项和股东投票；现金流转换与多公司比较也包含在同一工具面中。

宿主程序不预先计算 benchmark 答案。大模型决定应使用哪些证据并采用何种公式，也决定何时调用工具；宿主程序负责执行工具并记录过程，还会在最终答案前提示模型进行数值核验和覆盖检查。

## 关键实验协议

硬约束：

- 在线测试才能作为金融能力证据。
- fake/offline tests 只能作为结构回归和协议检查，也可用于编译或安全回归，但不能作为做题能力证据。
- gold/reference/scoring material 不进入模型上下文。
- 不使用答案表，不对题目打表，也不写入硬编码 benchmark 规则。
- 开发集合和测试集合必须区分；被人工分析过的题不能再当干净留出测试。

## 失败类型归因

当前失败主要来自更上层的金融推理和最终答案稳定性问题；基础工具链已经能够支撑多数题目的取证与计算：

1. 数值容差失败：多数失败来自数值提取和公式口径选择，也与单位换算和符号方向有关；期间处理以及最终答案完整性同样会影响评分。
2. 空最终答案：offset `121` 显示循环在长推理后仍可能进入 `empty_final_answer`，需要更强的最终回答恢复机制。
3. 长题成本：offset `143` 虽然通过，但消耗 `11.1M` tokens，说明证据对象搜索和重复取证仍有优化空间，收尾阶段也需要继续压缩。
4. 工具调用冗余：部分题在已有证据足够后仍继续检索，说明证据充分性判断和停止条件仍依赖模型能力和系统提示合同。
5. 数值核验覆盖不足：验证工具能检查显式数字，但不能替代模型判断 required facts 是否齐全。

## 智能体循环和通用能力还能优化什么

下面是下一阶段架构优化方向，均应保持 LLM 决策为核心，避免回到规则打表。

### 1. 最终回答可靠性

目标：减少空最终答案，避免模型把工具标记误写成最终答案，并降低证据已足够时仍答非所问的概率。

可做：

- 让模型先写最终答案草稿，再自审覆盖项和数值，最后输出正式答案。
- 在无工具收尾轮中保留更明确的答案格式要求。
- 对自指回答和过程性回答继续做通用恢复，空回答也应进入同一恢复流程。
- 将必要事实清单作为模型可见任务合同，宿主程序不代填答案。

### 2. 数值精度和单位纪律

目标：降低数值容差失败。

可做：

- 对所有关键数值主张要求使用计算器或数值核验器。
- 最终答案必须写出来源行项目和期间，并说明单位与公式以及代入过程。
- 比率和利润率应同时给出小数与百分比，回报率也采用同一表达方式；变化量应同时给出绝对变化和百分点变化。
- 平均值和期末值必须说明口径，同比计算也要明确财年天数以及币种单位。

### 3. 证据充分性控制

目标：减少“证据不足时过早回答”和“证据足够后继续乱搜”。

可做：

- 让模型维护轻量任务清单，记录事实取得情况和公式验证情况，并检查答案是否覆盖题目要求。
- 证据对象搜索和读取工具应返回更清晰的章节信息，同时提供标题与页码，帮助模型定位证据。
- 来源饱和检查点继续只收窄工具面，答案判断仍交给模型。

### 4. 成本和缓存优化

目标：保持高缓存命中率，同时降低长题 token 爆炸。

现状：

- 剩余 54 题严格评测的聚合缓存命中率已达 `89.06%`。
- 个别长题仍超 `5M` tokens。

可做：

- 稳定系统提示和工具协议，避免高频变动破坏缓存。
- 减少每轮临时上下文，保持 `model_context_mode=off` 作为默认。
- 将大证据放在证据对象中，通过窗口读取和片段返回。
- 做运行轨迹压缩时，应保留关键事实和来源说明，也要保留工具结果摘要，同时压缩重复工具调用历史。

### 5. 工具发现和金融工具台成熟度

目标：让模型在第一次理解任务时更清楚可用工具和调用方式。

可做：

- `finance.workbench.open` 应输出更短且结构更清楚的题型合同。
- 工具说明更贴近模型真实调用意图。
- 对高价值工具提供示例，但不包含 benchmark 答案。
- 延迟加载工具根据题型动态展开，减少初始工具面噪声。

### 6. 可报告的过程可观察性

目标：让智能体工作流能够作为可展示且可复现的实验材料。

可做：

- 保存运行事件时间线。
- 为每题记录循环轮数和工具调用次数，同时保存 token 用量与缓存命中率，并把成本以及通过情况和失败原因写入实验记录。
- 图表应覆盖分段通过率和成本分布，并展示循环轮数与工具调用之间的关系，同时呈现缓存命中率分布以及失败类型统计。
- 用 2-3 个典型案例展示智能体如何从题面理解推进到证据读取，再通过工具使用完成数值计算和结果核验，最后形成答案。

## 报告写作口径

可以说：

- “Kernel v4 已经形成成熟单智能体循环和金融工具链。”
- “FinanceBench debug50 是开发/调试集合，最佳记录为 50/50 在线通过。”
- “剩余未用于调试的 offsets 96-149 共 54 道，冻结配置在线严格结果为 42/54，通过率 77.78%。”

- “失败主要集中于数值精度和最终答案阶段，基础工具链已经能够支撑多数在线题目的取证和计算。”

不能说：

- “已经完成 clean test100 77%/80%/90%。”
- “debug50 结果代表泛化测试准确率。”
- “replay 题目是 held-out test。”
- “结构测试 passed 等于金融做题能力。”
