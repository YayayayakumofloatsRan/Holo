# 项目建议书：面向仿生 Holo Agent 的反应核意识流架构

日期：2026-05-24

## 项目名称

反应核意识流：面向持久化多模态 LLM Agent 的输入-理解-决策-行动-反馈仿生架构

## 摘要

本项目拟研究一种面向持久化 AI Agent 的仿生认知架构。我们并不主张系统具有真实人类意识、主观情绪或生物学意义上的心智，而是希望从工程和认知建模角度，构建一个能够持续接收输入、理解语境、形成决策、调用工具、执行行动、吸收反馈并改进自身状态的 Holo Agent 系统。当前多数基于大模型的 Agent 仍然接近“提示词-回复”的模式，即使加入 RAG、多轮对话或工具调用，也常出现上下文断裂、记忆提取不稳、连续回复同质化、行动反馈不能沉积为后续状态等问题。Holo 项目希望围绕“仿生”这一核心命题，将人类认知中可工程化的部分抽象为反应核、工作记忆、长期记忆、情绪/驱动状态、视觉场景、行动门控和反馈学习等模块，并用可视化方式展示其内部状态变化。

本项目的核心假设是：人类式第一反应可以近似建模为一个“反应核”作用于当前上下文、工作记忆、长期记忆、情绪状态、视觉状态、任务压力和过往反馈所形成的综合状态场。这个第一反应不是流程终点，而应写回工作记忆，改变系统状态，并决定是否需要进一步检索、推理、调用工具或表达。只有当后续表达具备新的语义功能时，系统才应继续输出；如果只是重复第一反应的同义表达，则应被抑制。通过这样的闭环，Holo 可以从普通聊天工具逐步发展为一个具有长期连续性、可解释内部状态和实际行动能力的多模态 Agent。

## 研究问题

本项目调查的问题是：在不训练基础大模型的前提下，能否通过 provider 以上的系统架构设计，使一个 LLM Agent 形成更稳定、更可测量、更接近生物认知流程的输入-理解-决策-行动-反馈闭环？

这个问题具有实际意义。当前 LLM 已经具备较强语言理解和推理能力，但单次调用或简单多轮调用并不能自然产生稳定主体、长期记忆、行动责任和持续改进能力。Holo 已经在实验中暴露出典型问题：第一句回答可能合理，但第二句经常只是同义复述；记忆系统有时不能准确提取；工具调用和内部思考流之间缺少清晰接口；视觉、环境、任务和长期关系状态还没有形成统一的状态场。这些问题不是单纯换一个更强模型就能完全解决的，而是需要研究如何组织发包、如何压缩上下文、如何使用记忆、如何决定是否继续推理，以及如何把行动结果写回系统。

因此，本项目的核心研究问题可以表述为：如何设计一种仿生 Agent 内核，使每一次外部输入、内部推理、工具调用、视觉观察和外部表达都能更新一个持久认知状态，并使后续发包由状态变化和任务需要驱动，而不是由固定模板或硬编码轮次驱动？

## 为什么值得用 AI 解决

该问题适合用 AI 解决，因为它涉及自然语言、长期记忆、多模态感知、工具调用、任务规划、情绪语气、关系状态和反馈学习等多种异质信息。传统规则系统很难在这些维度上保持灵活性，而大模型在语义压缩、意图理解、候选解释、计划生成和自然语言表达方面具有明显优势。与此同时，单独依赖大模型又会带来幻觉、上下文遗忘、成本不可控和责任边界不清等问题。

本项目采用的基本思路是：基础模型作为语言和推理处理器，Holo 本地内核负责连续性、记忆管理、工具权限、隐私边界、状态可视化和反馈沉积。由于高校和个人研究通常无法训练大型基础模型，provider 以上的适配层研究本身就具有价值。如何把有限长度的上下文包组织好，如何决定发多少个包、什么时候停止、什么时候调用更深模型、什么时候调用工具、什么时候写入记忆，是目前 Agent 系统走向实用化必须解决的问题。

## 背景阅读材料

本项目将重点阅读和参考以下方向。

1. 语言 Agent 的认知架构。CoALA 将语言 Agent 组织为记忆、行动空间和决策过程等模块，为 Holo 的模块化内核提供了理论参考。
   - https://arxiv.org/abs/2309.02427

2. 生成式 Agent 与反思机制。Generative Agents 说明观察、记忆检索、规划和反思对于可信行为具有重要作用。
   - https://arxiv.org/abs/2304.03442

3. 分层记忆和虚拟上下文管理。MemGPT 将 LLM Agent 看作具有多层记忆和上下文调度能力的系统，与 Holo 的 working/candidate/durable/archive 记忆结构具有相似问题意识。
   - https://arxiv.org/abs/2310.08560

4. 推理-行动闭环。ReAct、Reflexion、Tree of Thoughts 等工作表明，将推理、行动、反馈和记忆结合起来，可以提升 Agent 的任务表现和自我修正能力。
   - https://arxiv.org/abs/2210.03629
   - https://arxiv.org/abs/2303.11366
   - https://arxiv.org/abs/2305.10601

5. 世界模型和多模态行动模型。World Models、RT-2、Genie 和 V-JEPA 等工作提示我们，未来 Agent 不应只有文本接口，还应逐步引入视觉、环境和行动反馈。
   - https://arxiv.org/abs/1803.10122
   - https://arxiv.org/abs/2307.15818
   - https://arxiv.org/abs/2402.15391
   - https://ai.meta.com/blog/v-jepa-yann-lecun-ai-model-video-joint-embedding-predictive-architecture/

6. DeepSeek reasoner 和工具调用文档。DeepSeek reasoner 可用于更深层的内部推理包，DeepSeek API 的工具调用能力可用于构建实际行动链路。
   - https://api-docs.deepseek.com/guides/reasoning_model

## 数据来源与采集方式

项目将使用四类数据。

第一类是对话和交互日志，包括 Holo CLI、WeChat、未来独立会话端和系统调试过程中的输入输出。数据内容包括用户输入、Holo 回复、回复分段、时间间隔、选择的行动、用户纠正和失败记录。

第二类是内部 trace 数据，包括每次发包的元数据、激活的记忆锚点、向量检索结果、是否继续推理的门控值、语义新颖度、工具调用请求、工具返回结果和自我反思记录。这类数据是研究意识流可视化和状态连续性的关键。

第三类是多模态观察数据。初期可以从本机摄像头采集低频快照或短帧窗口，用视觉模型生成场景描述、物体状态、环境变化和视觉 embedding。默认不保存原始视频，只保存经过压缩和脱敏的状态表示，除非用户明确允许。

第四类是评测数据，包括人工构造的对话场景、记忆召回测试、工具调用任务、视觉 grounding 任务、长周期连续性测试，以及自回声、重复表达、幻觉记忆、不当工具调用等失败案例。

数据采集应坚持本地优先、可回放、可匿名化和可删除原则。涉及个人聊天、摄像头画面和私有记忆的数据默认不外发，公开实验只使用合成数据、脱敏样例或派生指标。

## 方法与算法设计

本项目提出“反应核意识流模型”（Reaction-Kernel Conscious Stream Model, RK-CSM）。在每个时间步，Holo 从 CLI、WeChat、摄像头、文件、工具结果等通道接收输入 `x_t`，并构建综合状态场：

```text
S_t = Phi(x_t, C_t, W_t, M_t, A_t, V_t, G_t, O_t)
```

其中：

- `C_t` 表示当前对话上下文；
- `W_t` 表示工作记忆和当前线程状态；
- `M_t` 表示长期记忆、候选记忆和检索锚点；
- `A_t` 表示情绪、驱动、压力和社交姿态；
- `V_t` 表示视觉或多模态场景状态；
- `G_t` 表示目标、承诺和任务世界状态；
- `O_t` 表示过往行动结果、错误和用户反馈。

第一反应可表示为：

```text
R_t^0 = K_theta (*) S_t
```

这里的 `K_theta` 是反应核，代表系统长期形成的反应倾向、表达约束、风险偏好、关系先验和行动偏置。它不是基础模型参数，而是 Holo 本地可更新的状态参数层，可由用户反馈、失败案例、长期互动和自我反思逐步调整。

第一包完成后，系统必须写入状态增量：

```text
Delta S_t^0 = observe(R_t^0, selected_action, visible_reply, internal_packet)
```

随后由继续门控判断是否需要更深处理：

```text
continue_t = g(uncertainty, novelty_gap, unfinished_task, tool_need, affect_pressure, risk, user_wait_cost)
```

如果门控关闭，系统停止输出。如果门控打开，Holo 再调用更深模型，例如 DeepSeek reasoner。第二包不能简单要求“再说一句”，而必须携带第一包已经完成的语义功能、尚未完成的任务、不能重复的内容和可能需要调用的工具。第二个外显 bubble 只有在具备明确新功能时才允许出现，例如澄清、纠错、追问、解释、承诺、工具执行、风险提示或总结。

工具调用作为行动进入同一闭环。读操作、检索操作、摄像头观察和文件检查可设定较低权限；修改文件、发送消息、调用外部服务和改变记忆状态需要更严格的权限门控和审计记录。视觉输入不应被当作无限制 prompt 填料，而应转化为受控的 scene-state delta。

## 系统实现路线

本项目应复用现有 Holo runtime，而不是创建第二个主脑。WSL Holo host 仍然是唯一主脑；Windows、WeChat、摄像头和未来移动端都只是传输层或感知层。可复用模块包括：

- processor fabric 多模型通道；
- memory warehouse 和 memory fabric；
- working/candidate/durable/archive 记忆层；
- 工具调用适配器；
- CLI 与 WeChat transport；
- Stage131/132 thought-flow trace 和 CT 可视化；
- DeepSeek provider backend。

在此基础上，项目将重点新增或强化：

1. 反应核参数层；
2. 每包后的 state-delta 记录；
3. 语义新颖度和冗余度评分；
4. 多 bubble 的语义角色门控；
5. 可视化的意识流 CT 工作台；
6. 摄像头输入与视觉场景状态；
7. DeepSeek reasoner 的条件调用；
8. 工具调用与反馈写回；
9. 自我反思和自我修复流程。

## 可视化设计

可视化不是展示效果的附属品，而是本项目的研究仪器。系统应提供类似“仿生 CT”的工作台，展示以下内容：

- 当前输入通道和时间；
- 激活的记忆锚点及强度；
- 工作记忆场在每次发包前后的变化；
- 反应核的激活情况；
- 是否继续推理的门控值；
- 多个 bubble 之间的语义新颖度；
- 被选择的行动和被压制的候选行动；
- 工具调用图；
- 视觉场景 embedding 和变化；
- 记忆写入深度。

通过这些图形化指标，可以判断 Holo 是否真正形成了连续的状态轨迹，还是只是在生成多个文本片段。

## 预期改进

相对于普通聊天工具、普通 RAG 或简单多轮 Agent，本项目预期带来以下改进：

1. 减少同质化二连回复，使每个输出片段具备明确语义功能；
2. 提高长期记忆召回的稳定性和可解释性；
3. 让内部推理、工具调用和外部表达共享同一状态轨迹；
4. 通过视觉输入使 Holo 能够感知现实环境或桌面状态；
5. 通过反馈写回提升用户纠正后的修复能力；
6. 通过可视化降低调试成本，便于发现自回声、幻觉和记忆污染；
7. 通过权限门控和审计机制，使工具调用更接近可部署系统。

## 评测方案

实验将比较以下系统：

- 单次大模型调用基线；
- 普通 RAG 基线；
- 固定两句回复基线；
- 无 state-delta 的多包推理基线；
- 完整 RK-CSM 系统。

主要指标包括：

- 回复片段之间的语义新颖度；
- 重复率和同义复述率；
- 记忆召回准确率；
- 幻觉记忆率；
- 工具调用成功率与误调用率；
- 延迟和 token 成本；
- 用户纠正后的采纳率；
- 多日连续对话中的一致性；
- 摄像头接入后的视觉 grounding 准确率；
- 高权限工具的安全门控准确率。

人工评测可采用盲测比较，评价自然性、有用性、记忆正确性、连续性和边界意识。自动评测可使用固定 probe、回放对话、合成任务和失败案例集。

## 消融实验

计划进行以下消融：

1. 移除反应核，观察第一反应一致性和风格稳定性是否下降；
2. 移除工作记忆写回，观察第二包是否退化为同义复述；
3. 移除语义新颖度门控，测量重复 bubble 增加情况；
4. 移除长期记忆检索，测量记忆召回错误率；
5. 移除情绪/驱动状态，评估语气和社交适配能力；
6. 移除视觉场景状态，评估多模态任务下降情况；
7. 仅使用 flash 模型，不调用 reasoner，比较成本、延迟和质量；
8. 禁用工具调用，评估任务完成率和幻觉率；
9. 禁用自我反思，评估用户纠正后的恢复能力。

## 失败情况与能力边界

本项目需要明确边界。Holo 不是人类，也不应声称具有真实意识、真实情绪或生物神经系统。我们研究的是功能仿生和工程近似，即如何让一个 LLM Agent 形成更好的连续状态、记忆使用和行动反馈。

可能失败的情况包括：记忆污染、过度拟合某种人格语气、幻觉式回忆、过度继续发包、工具误用、视觉误读、自回声、隐私泄漏和成本失控。系统还可能把“仿生表达”误发展成过度拟人化语言，这需要通过提示约束、评测和可视化监控加以控制。

摄像头接口尤其需要谨慎。默认应要求用户显式开启，并显示采集状态。初期应优先保存派生描述和 embedding，而不是原始视频。涉及人脸、私人屏幕、实验数据和聊天内容时，需要脱敏和本地处理优先。高风险工具调用必须经过权限确认和审计记录。

## 科研与生产环境中的进一步优化

若进入科研环境，需要：

- 固定版本的 prompt 和配置；
- 可复现的 trace replay；
- 脱敏评测集；
- 消融实验脚本；
- 失败案例库；
- 可导出的可视化报告；
- 伦理和隐私说明。

若进入生产或实验室长期使用环境，还需要：

- 成本和资源调度器；
- 多 provider 兼容性测试；
- 摄像头和工具权限管理；
- 本地模型或本地视觉推理 fallback；
- 记忆重置、快照和回滚机制；
- 幻觉、重复、自回声和危险行动监控；
- 用户可理解的状态面板。

## 预期贡献

本项目的预期贡献不是简单“给 Agent 加记忆”或“让 Agent 多调用几次模型”，而是提出并实现一个闭环系统：反应核、工作记忆状态更新、继续门控、reasoner 发包、工具/视觉行动、反馈写回和 CT 式可视化。该系统可用于研究 provider-based LLM Agent 如何在不训练基础模型的情况下，通过外层认知架构提升连续性、可靠性和实际行动能力。

从应用角度看，Holo 将成为一个具有长期记忆、多模态感知、工具行动和自我改进能力的个人/实验室 Agent。从科研角度看，Holo 可以作为研究功能仿生认知架构、Agent memory、test-time compute、工具调用和多模态世界模型整合的实验平台。若实验证明 RK-CSM 在重复率、记忆正确性、工具成功率、用户纠正采纳率和长周期一致性上优于现有基线，则该工作具备形成论文、系统 demo 和后续开源基准的潜力。
